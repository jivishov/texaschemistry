## Build
1. **Round shapes as discs.** `circle`, `electron` and `badge` shapes keep their centre and radius (stroke included as today). A label box against a disc: the label is *inside* the disc when all four corners lie within r − 2 px of the centre; it *cuts* the disc when the box's nearest point to the centre lies within r − 2 px and the label is not inside; otherwise no intersection. `rrect` stays a rectangle. Report the shape kind as today.
2. **Inline text is part of its block.** In the DOM pass, only block-level boxes take part: elements whose computed display is `block`, `flex`, `grid`, `list-item`, `table-cell`, `table-row` or `inline-block` *when the element is a card, chip, badge, option or footer span by the existing class lists*; an element of inline display (`sup`, `sub`, `b`, `span`, `i`, `.es`, `.nw`, `.gap`, inline formulas) and an inline-block that is none of those classes are part of their nearest block ancestor and are not separate boxes. The box of a block is its border box as today. Keep the existing kinds (`text`, `card`, `chip`, `footer`), containment and ancestor rules.
3. **`D.spheres` scenes.** Wrap `Deck.spheres` the way `canvasSim` is wrapped (a setter installed when the Deck object is assigned), so every label and shape recorded during a `spheres` call carries a scene number. Within one scene no label-against-label and no label-against-shape test runs (the renderer draws far to near, so a nearer sphere hiding part of a farther symbol is depth, not overlap, and every symbol sits inside its own sphere). Labels and shapes of a scene are still tested against everything outside the scene. Record the number of scenes and their boxes in the summary.
4. **Hidden labels.** A label whose box lies fully (within 2 px) under a shape drawn later in the same paint with an opaque fill (fill alpha 0.9 or more and `globalAlpha` 0.9 or more at the call) is hidden, not visible: drop it from the tests and count it as "covered labels" in the frame's record and the summary (reported, never a failure). A label only partly under such a shape stays an intersection (item 1's test for discs, the rectangle test for `rrect`).
5. **The motion-on pass for live stages.** The proxy records `host.__live = !!(spec.live && spec.live(info.stage))` at each paint. After the reduced-motion pass, collect the frames on which a visible canvas reported `__live`; open a second context with motion on (`reduced: false`, same theme, the same `init`), and for each such frame `Deck.go(s, f)`, wait 1.4 s, run the overlap check, wait a further 1.0 s, run it again; the same assertions and output lines, tagged `s<N>f<F>@live1` and `@live2`; include these in `overlap-<theme>.txt`, `layout-<theme>.json` and the verdict line ("live: K frames at two moments"). Settle is not needed there (the stage runs on purpose). 4.1 slide 10 has live stages; use it to prove the pass.
6. **Baselines for the reference decks.** A registry field `overlap_baseline` (a path relative to the kit, optional; absent for a new deck) names a JSON file of accepted intersections, each `{"frame": "s10f1", "a": "<the A string as the audit prints it>", "b": "<the B string>"}` (strings, not coordinates, so small drifts do not matter; the `@live1`/`@live2` tags are part of the frame). A hit that matches a baseline entry is counted as "baselined" and not a failure; a hit with no entry fails as today; baseline entries that no hit matches are printed as "stale baseline entries" (not a failure). After items 1 to 5, run the audit on 4.1 and 4.2 (light), read the remaining hits, and write `parts/lessons/4-1/overlap-baseline.json` and `parts/lessons/4-2/overlap-baseline.json` from them with a small one-off script in the scratchpad (do not add a baseline-writing flag to the kit: the baseline is a record the orchestrator and the teacher review, not a tool). Add the field to both registry entries. The README says what a baseline is, that only the two decks built before the no-overlap rule have one, and that a new deck gets none.
7. **Two stale texts.** The README's `keys_cfg` row: the `tm` slide is the one whose frame 1 starts a timer, and the audit reads that timer's own length. `split_parts.py`'s docstring example: `css-51` in place of 4.5's marker.
